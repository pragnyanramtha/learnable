**1. What is an algorithm?**
A. A clear set of steps for solving a problem | B. A file format for spreadsheets | C. A Python error message | D. A style of comment only
<Answer: A. A clear set of steps for solving a problem>
<Explanation: Algorithms describe how to transform input into a result.>

**2. What is pseudocode used for?**
A. Planning logic in human-readable steps | B. Encrypting Python files | C. Replacing all tests | D. Formatting CSV files
<Answer: A. Planning logic in human-readable steps>
<Explanation: Pseudocode helps design the algorithm before writing real code.>

**3. How does linear search work?**
A. It checks items one by one | B. It always starts in the middle | C. It sorts before every comparison | D. It only works on dictionaries
<Answer: A. It checks items one by one>
<Explanation: Linear search walks through values until it finds the target or reaches the end.>

**4. What is the worst-case running time of linear search?**
A. O(n) | B. O(1) | C. O(log n) | D. O(n log n)
<Answer: A. O(n)>
<Explanation: In the worst case, linear search may check every item.>

**5. What condition must be true before binary search is used?**
A. The list must be sorted | B. The list must contain only strings | C. The list must be empty | D. The list must come from a CSV file
<Answer: A. The list must be sorted>
<Explanation: Binary search discards halves based on order, so unsorted data breaks that logic.>

**6. Why is binary search efficient?**
A. It removes about half of the remaining search space each step | B. It checks every item twice | C. It never uses comparisons | D. It works only on one-item lists
<Answer: A. It removes about half of the remaining search space each step>
<Explanation: Halving the problem leads to logarithmic growth.>

**7. What running time is commonly associated with binary search?**
A. O(log n) | B. O(n^2) | C. O(n) | D. O(1) for every input
<Answer: A. O(log n)>
<Explanation: Binary search repeatedly cuts the remaining data in half.>

**8. What does Big O usually describe?**
A. An upper bound on how an algorithm grows | B. The exact number of Python files | C. Only the best possible case | D. The name of a package
<Answer: A. An upper bound on how an algorithm grows>
<Explanation: Big O is often used to discuss worst-case growth.>

**9. Which running time grows fastest among these choices?**
A. O(n^2) | B. O(n) | C. O(log n) | D. O(1)
<Answer: A. O(n^2)>
<Explanation: Quadratic time grows much faster as n becomes large.>

**10. What does sorting do?**
A. Arranges values in a useful order | B. Deletes all strings | C. Opens files automatically | D. Turns lists into exceptions
<Answer: A. Arranges values in a useful order>
<Explanation: Sorting can arrange numbers, words, or records by a chosen rule.>

**11. How does selection sort choose what to place next?**
A. It finds the smallest remaining value | B. It always picks a random value | C. It splits the list in half first | D. It only compares the first two values
<Answer: A. It finds the smallest remaining value>
<Explanation: Selection sort repeatedly selects the next smallest item.>

**12. How does bubble sort move larger values?**
A. By repeatedly swapping neighboring values that are out of order | B. By using regex groups | C. By reading from a CSV | D. By removing all duplicates
<Answer: A. By repeatedly swapping neighboring values that are out of order>
<Explanation: Larger values move toward the end through repeated swaps.>

**13. What is recursion?**
A. A function calling itself | B. A list becoming a dictionary | C. A file being overwritten | D. A regex matching a number
<Answer: A. A function calling itself>
<Explanation: Recursive functions solve a problem by calling themselves on smaller input.>

**14. What is a base case in recursion?**
A. The condition that stops the recursive calls | B. The slowest sorting algorithm | C. The first item in every list | D. The name of a CSV heading
<Answer: A. The condition that stops the recursive calls>
<Explanation: Without a base case, recursion can continue until an error occurs.>

**15. What is the main strategy of merge sort?**
A. Split the list, sort each half, then merge the sorted halves | B. Check only the first item | C. Swap random neighbors forever | D. Convert numbers to strings
<Answer: A. Split the list, sort each half, then merge the sorted halves>
<Explanation: Merge sort uses divide and conquer, giving it O(n log n) running time.>
